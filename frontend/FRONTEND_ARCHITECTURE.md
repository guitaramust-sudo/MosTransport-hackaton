# Архитектура frontend

## Технологии

- React + TypeScript
- Vite
- SCSS
- React Router
- TanStack React Query — серверное состояние и запросы к API
- Redux Toolkit — глобальное клиентское состояние приложения

## Структура каталогов

```text
src/
├── app/
│   ├── router.tsx          # Конфигурация маршрутов
│   ├── store.ts            # Redux store
│   ├── queryClient.ts      # Настройки React Query
│   └── providers.tsx       # Общие провайдеры приложения
├── components/             # Компоненты страниц и сущностей
│   ├── common/             # Переиспользуемые UI-компоненты
│   └── entities/           # Компоненты предметной области
├── helpers/
│   ├── _variables.scss     # Фиксированные SCSS-переменные и токены
│   ├── _mixins.scss        # SCSS-миксины
│   ├── _functions.scss     # SCSS-функции
│   └── index.scss          # Единая точка подключения helpers
├── pages/                  # Компоненты страниц верхнего уровня
├── types/                  # TypeScript-типы сущностей
├── App.tsx                 # Только Outlet для дочерних маршрутов
└── main.tsx                # Запуск приложения и подключение провайдеров
```

## Ответственность каталогов

### `helpers`

Каталог содержит общие инструменты SCSS:

- `_variables.scss` — цвета, размеры, breakpoints, z-index и другие фиксированные значения;
- `_mixins.scss` — медиазапросы, типографика, flex/grid-шаблоны и повторяемые наборы правил;
- `_functions.scss` — вычисления и преобразования значений;
- `index.scss` — экспорт всех helpers через `@forward`.

Компоненты подключают helpers через `@use`, не копируют фиксированные значения и повторяемые правила локально.

```scss
// helpers/index.scss
@forward 'variables';
@forward 'mixins';
@forward 'functions';
```

```scss
// components/common/Button/Button.module.scss
@use '@/helpers' as h;

.button {
  color: h.$color-primary;
  @include h.flex-center;
}
```

### `types`

Каталог содержит типы предметных сущностей и общие контракты приложения. Типы группируются по сущностям, например:

```text
types/
├── route.ts
├── station.ts
├── transport.ts
└── index.ts
```

Типы, относящиеся только к props одного компонента, можно оставить рядом с компонентом. Типы API-моделей и сущностей должны находиться в `types`.

### `pages`

Каждая страница соответствует маршруту. Страница собирает готовые компоненты, запускает необходимые hooks и описывает компоновку экрана. В страницах не следует размещать сложные переиспользуемые UI-блоки.

```text
pages/
├── HomePage/
│   └── HomePage.tsx
└── NotFoundPage/
    └── NotFoundPage.tsx
```

### `components`

Каталог содержит:

- общие UI-компоненты;
- компоненты конкретных страниц;
- компоненты сущностей предметной области.

Компонент хранится вместе со своими стилями, тестами и локальными типами:

```text
components/entities/TransportCard/
├── TransportCard.tsx
├── TransportCard.module.scss
└── TransportCard.types.ts
```

## Точка входа и маршрутизация

`App.tsx` является корневым route-компонентом и содержит только `Outlet`:

```tsx
import { Outlet } from 'react-router-dom'

function App() {
  return <Outlet />
}

export default App
```

Все маршруты задаются централизованно в `app/router.tsx`. Страницы должны загружаться через конфигурацию роутера. Для неизвестного URL обязательно предусматривается страница `NotFoundPage`.

## Управление состоянием

### React Query

React Query используется для серверного состояния:

- HTTP-запросов;
- кеширования ответов API;
- состояний загрузки и ошибок;
- повторных запросов и инвалидации кеша;
- мутаций данных на сервере.

Единый `QueryClient` создаётся в `app/queryClient.ts` и подключается через `QueryClientProvider` в `app/providers.tsx`.

Данные API не следует дублировать в Redux. Для запросов создаются именованные hooks, например `useTransportRoutes` и `useUpdateRoute`.

### Redux Toolkit

Redux используется только для глобального клиентского состояния:

- состояния интерфейса;
- пользовательских настроек;
- глобальных фильтров;
- данных, которые нужны нескольким независимым веткам компонентов и не являются серверным кешем.

Store создаётся через `configureStore`. Доступ к состоянию выполняется через типизированные hooks `useAppDispatch` и `useAppSelector`.

Локальное состояние компонента остаётся в `useState` или `useReducer`, если оно не требуется в других частях приложения.

## Провайдеры

Все глобальные провайдеры подключаются в одном компоненте `app/providers.tsx`:

```tsx
<Provider store={store}>
  <QueryClientProvider client={queryClient}>
    <RouterProvider router={router} />
  </QueryClientProvider>
</Provider>
```

`main.tsx` должен только находить DOM-контейнер и рендерить корневой компонент с провайдерами.

## Запрет prop drilling

Нельзя передавать данные через несколько промежуточных компонентов, которым эти данные не нужны.

Вместо prop drilling используются:

- React Query hooks — для серверных данных;
- Redux selectors и actions — для глобального клиентского состояния;
- React Context — для ограниченного состояния отдельной функциональной области;
- композиция компонентов — для UI-зависимостей;
- локальные hooks — для переиспользуемой логики.

Props используются для прямого контракта между родительским и дочерним компонентами. Передача props на один уровень не считается prop drilling.

## Правила зависимостей

1. `pages` могут импортировать `components`, `types`, hooks и `helpers`.
2. `components` не должны импортировать `pages`.
3. Общие компоненты не должны зависеть от компонентов конкретной страницы.
4. Компоненты не выполняют HTTP-запросы напрямую — запросы инкапсулируются в React Query hooks.
5. Серверные данные не копируются в Redux без отдельной обоснованной причины.
6. В компонентах запрещены неописанные `any` и дублирование типов сущностей.
7. Для импортов рекомендуется настроить alias `@` на каталог `src`.

## Добавление новой функциональности

При добавлении новой страницы необходимо:

1. Создать типы сущностей в `types`, если они используются более чем одним компонентом.
2. Создать React Query hooks для взаимодействия с API.
3. Добавить Redux slice только при наличии глобального клиентского состояния.
4. Создать компоненты страницы и сущностей в `components`.
5. Собрать страницу в `pages`.
6. Зарегистрировать маршрут в `app/router.tsx`.
7. Добавить SCSS-переменные, функции или миксины в `helpers`, если они переиспользуются.
8. Проверить TypeScript, lint и production-сборку.
