# ВСМ — игровой тренажёр проводника

Хакатонный прототип для отработки работы с пассажирами в виртуальном вагоне. Проводник изучает короткую теорию, выполняет задачи в 3D-среде, принимает решения в игровых ситуациях и получает разбор их последствий.

> **Статус:** демонстрационная сборка. Учебный контент помечен `draft`; игровые оценки не являются официальной аттестацией сотрудника.

## Что можно показать

- **Учебный маршрут First:** первая глава с уроками B01 «Первый маршрут» и B02 «Первый разговор». Каждый урок включает теорию, проверку, практику в вагоне, итоговую проверку и разбор.
- **3D-практика:** перемещение по вагону, осмотр учебных точек, наблюдение за пассажирами, разговор и действия с доступными предметами.
- **Дополнительные игровые режимы:** рейс в вагоне, последовательная диалоговая смена и отдельная ветвящаяся демо-симуляция. Это разные потоки; ветвящаяся симуляция не является частью 3D-уроков.
- **Игровой прогресс:** профиль, XP, бейджи уроков, достижения и накопительный рейтинг. Призовые очки учитываются отдельно от XP и рейтинга.

Полный путь пользователя и конкретные примеры приведены в [User Flow](docs/user-flow.md). Что осталось в пределах прототипа и как проект будет развиваться — в [ограничениях и плане развития](docs/limitations-and-roadmap.md).

## Быстрый запуск

Нужен Docker с поддержкой Compose. Из корня репозитория:

1. Скопируйте `backend/.env.example` в `backend/.env` и задайте `ADMIN_BOOTSTRAP_EMAIL` и `ADMIN_BOOTSTRAP_PASSWORD` для демонстрационного администратора. Не добавляйте `.env` и реальные ключи в Git.
2. Запустите проект:

   ```bash
   docker compose up --build
   ```

3. Откройте приложение: **http://localhost:8081**. API доступен на **http://localhost:8088**; проверка готовности — **http://localhost:8088/readyz**.
4. Войдите под администратором и создайте учебный аккаунт проводника. Публичной регистрации нет; порядок создания аккаунтов описан в [инструкции backend](backend/README.md#первоначальная-настройка).

По умолчанию диалоговая модель работает в локальном mock-режиме, поэтому для запуска не нужны ключи GigaChat. Для запуска мобильного клиента отдельно см. [инструкцию frontend](frontend/README.md). **Android push в Expo Go не работает**: для проверки доставки требуется собственная development build и настройка по [инструкции push](frontend/docs/PUSH_NOTIFICATIONS.md).

## Архитектура и документация для сдачи

Клиент Expo/React Native обращается к Go API по HTTP и WebSocket. Сервис хранит состояние и прогресс в PostgreSQL. Диалоговая смена, ветвящаяся демо-симуляция и вагонный режим существуют отдельно; учебный курс использует вагонный режим.

**Российская языковая модель.** Диалоговый движок поддерживает [GigaChat-2 от Сбера](https://developers.sber.ru/docs/ru/gigachat/guides/selecting-a-model). При `LLM_MODE=gigachat` он обращается к российскому API и не требует зарубежного LLM-сервиса. Для запуска без ключей по умолчанию используется локальный mock. Таким образом, импортонезависимость относится к нейросетевому компоненту; весь проект включает международные технологии (Expo/React Native, Go, PostgreSQL), поэтому заявлять полную импортонезависимость продукта было бы неточно.

## Границы демонстрации

Полный учебный цикл подготовлен для First в первой главе. Наличие технических конфигураций других классов или отдельной 3D-модели экономкласса не означает, что для них готовы учебные сценарии. Временный интерфейс позволяет пройти демонстрационный путь, но ещё требует доработки перед промышленным использованием. Подробности — в [документе об ограничениях](docs/limitations-and-roadmap.md).
