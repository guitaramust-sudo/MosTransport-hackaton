# Проверка реализации

Проверено локально на ветке `dev-backend` с PostgreSQL 16 и `LLM_MODE=mock`.

## Автоматические проверки

- `go build ./...`, `go vet ./...`, `TEST_DATABASE_URL=... go test ./...` — успешно.
- `npm run typecheck`, `npx expo export --platform web` — успешно.
- `docker compose up -d --build backend`, `GET /healthz`, `GET /readyz`, `GET /metrics` — успешно.

## Сквозной сценарий

Через HTTP проверены регистрация, начало смены из четырёх ситуаций, диалог,
явная эскалация, закрытие ситуации, завершение смены и профиль. Повторное
закрытие ситуации возвращает 409. Повторное завершение смены возвращает тот же
XP и не начисляет его второй раз. Фоновый воркер закрыл ситуацию с истёкшим
таймером как `timeout`, сохранив `remarks` и `score_result`. Использованный
refresh-токен не принимается повторно (401).

В Expo web проверены вход, начало смены, ответ пассажира, закрытие ситуации и
экран итогового разбора. В UI отображается язык пассажира.

## Расхождение в исходном SPEC.md

Таблица замечаний §5.3 задаёт для примера §4.7 дельту лояльности
`fast +5`, `empathic +10`, `missed_point −5` = **+10**, то есть итог **60**
при начальных 50. Пример §4.7 и критерий приёмки §11 указывают **55**.
Реализация и тест следуют таблице замечаний; остальные значения примера
совпадают: `partial`, 20 XP, безопасность 65.

Проверка реального GigaChat требует ключей доступа. Локально проверены ретраи
HTTP 5xx и отказ от ретрая при 4xx через тестовый сервер.
